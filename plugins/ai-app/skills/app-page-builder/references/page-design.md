# 页面设计方法

## 从用户要完成的工作选择结构

| 用户任务       | 页面主结构                         | 首要交互                           |
| -------------- | ---------------------------------- | ---------------------------------- |
| 判断经营状况   | 关键指标、变化依据、异常或构成明细 | 调整时间和范围，进入异常来源       |
| 处理日常业务   | 待处理列表、筛选、选中项详情与动作 | 定位目标、查看上下文、执行一次操作 |
| 查看客户或项目 | 身份与状态、相关业务分区、关键活动 | 在关联对象之间定位，更新明确字段   |
| 探索数据关系   | 控制区、比较视图、可追溯明细       | 选择维度与范围，解释比较差异       |

页面主区域服务用户的首要任务。已有品牌和主题沿用其 token 与组件；工具没有提供组件库时使用可移植的语义化 HTML、CSS 和简单 SVG，不能假定图表库或远程字体已被打包。

## 先写页面与数据的对应关系

例如“销售和财务的回款工作台”可形成以下设计依据：

| 区域         | 业务依据                         | binding／来源                   | 交互                     |
| ------------ | -------------------------------- | ------------------------------- | ------------------------ |
| 订单总额     | 相同币种、相同业务周期的成交订单 | sales/orders，aggregate         | 展开订单范围与口径       |
| 待处理发票   | 当前查看者可见且待处理的发票     | finance/invoices，records       | 筛选、查看单据           |
| 记录状态操作 | 当前选中发票的合法状态变化       | finance/invoices，action/update | 用户提交后沿受控桥接更新 |

跨来源“未收金额”不能直接拿两个不同时段或不同粒度的总额相减。先确认共同订单键、取消和退款规则、币种及一对多关系。无法证明口径时显示各来源原指标，说明尚缺的比较依据。

筛选器要能落到真实绑定操作。当前绑定合同未提供运行时参数化协议时，不把一个月份选择器渲染出来就声称它已重新查询；在桥接接好后验证筛选是否同时更新相关指标和明细。

## 源码按职责组织

复杂页面可采用入口、数据转换、区域组件和样式文件。简单页面无需为每个标签建组件。以下是一个有多个区域的参考组织，实际文件随任务增减：

```text
src/Page.tsx                 页面结构和区域状态编排
src/presentation.ts          类型值到展示模型的转换
src/components/Summary.tsx   指标与口径
src/components/RecordList.tsx 记录列表、选择与详情
src/page.css                 主题适配与响应式布局
```

领域原值与展示值分开：number 保留十进制，select 用定义解析标签，user 与 link 使用可解析身份，date 与 date_time 使用各自时间语义。业务判断和写入使用原值，舍入、截断和名称只用于展示。

## 每个数据区域的状态

| 状态         | 用户能看到和做到什么                         |
| ------------ | -------------------------------------------- |
| 未接入／未知 | 明确未取得数据，避免显示零或成功状态         |
| 加载         | 保留区域结构和任务上下文，动作暂不可重复提交 |
| 空结果       | 表达当前筛选无结果，允许调整范围             |
| 被拒绝       | 标出不能访问的来源或动作，不暴露隐藏内容     |
| 错误         | 保留筛选和输入，给对应区域重试入口           |
| 部分可用     | 可用区域继续呈现，受影响指标注明缺口         |
| 已填充       | 值、单位、口径和主要操作清楚可辨             |

只在一项指标有真实零值时显示零。一个来源失败不自动清空其他来源的结果；多个来源也不承诺同步快照。

交互完成还要有键盘焦点、控件标签、窄屏阅读顺序和清楚的状态反馈。图表应让用户能取得关键数值，状态不能只靠颜色区分。没有实际预览与操作工具时，把这些作为源码检查项交付，不声称已经完成视觉或交互验收。
