# 插件诊断

先收集事实再下结论：问用户看到的原文（诊断与状态文案）、所在页面与操作序列；能读文件的场景先读声明与正文再判断。处置只给一条，改完后请用户重试一次再下结论。

按症状查表：

| 症状                                                 | 原因                                                   | 处置                                                                                                                                                               |
| ---------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 技能没进清单，`/技能名` 不命中                       | 插件被全局关闭；或技能被校验丢弃；或被自管同名技能遮蔽 | 依次核对：插件工作区开关 → 候选评审/诊断（description 空、插件技能名与目录不同名都会丢弃）→ 是否存在同名项目或个人技能（项目 ＞ 个人 ＞ 插件 ＞ 内置，遮蔽记诊断） |
| 清单里有，模型没按技能行事                           | 渐进披露：清单只给 name 与 description                 | 按条目 location 先完整读取 SKILL.md 再动手                                                                                                                         |
| 刚安装/改完技能，本条消息不生效                      | 发现按 Run 冻结                                        | 下一条消息生效，无需处理                                                                                                                                           |
| `/技能名` 打了没反应                                 | 词法未命中：须空白分界的 `/` 加全等词                  | 检查是否中文连写、紧贴标点或拼写偏差；未命中的 `/词` 原样保留不是错误                                                                                              |
| 安装被拒，提示 official release is revoked           | 官方目录吊销了该发布身份（reason 随诊断给出）          | 不绕过；换目录内可用版本或替代插件。已安装的仅显示吊销警示，安装与启用事实不变，停用与否由用户决定                                                                 |
| 安装报名称冲突                                       | 同一账号已有同名插件                                   | 先卸载再安装；自行导入的没有覆盖式更新                                                                                                                             |
| `builtin.plugin_install` 返回 requires startup trust | 含 Stdio 接入的候选需要启动信任，对话内不直装          | 打成 ZIP 指引用户走插件页「上传插件压缩包」候选确认                                                                                                                |
| 插件详情里接入显示「需要登录」                       | 安装不等于授权；连接就绪是运行期事实                   | 指引用户在插件详情完成该接入的授权；授权与插件启用相互独立                                                                                                         |
| Stdio 接入启动失败                                   | 外部程序缺失、包内入口路径或 cwd 声明问题              | 按诊断原文逐条处理；command 必须在安装环境中真实存在，外部依赖不在发布冻结范围                                                                                     |
| 更新失败或状态未知                                   | 候选校验失败或结果未确认                               | 旧版本继续可用；「未知」不是「已是最新」，如实呈现并重试。仅官方目录插件有受管更新，ZIP / Git / 本地导入是固定快照                                                 |
| 官方目录条目装不上，提示来源冲突                     | 目录对同一身份的绑定发生变化                           | 不安装，如实上报，等待目录侧澄清                                                                                                                                   |
| 项目技能整体没加载                                   | 项目信任未决或不受信                                   | 让用户在产品里完成信任决策；个人、系统与插件层不受此门控                                                                                                           |

组织共创或发布问题先读取 [组织共创流程](../plugin-creator/references/organization-sharing.md)，装载实际只读工具，区分资格未知、无席位、待审、批准、拒绝、过期与正式发布。响应中断先按原提案和修订用 receiptOnly 核对事实；正式发布回执不代表本机已安装。缺失新工具时交付包及升级缺口，旧 ZIP 或路径形式继续遵循同一审核门。

守则：只诊断与指引。安装、启用、卸载、授权与信任决策都由用户在产品里发起；不伪造「已修复」，处置后以用户重试的结果为准。
