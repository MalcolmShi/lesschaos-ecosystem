# 客制化官方插件

官方插件内容不可变：安装副本按摘要校验、随官方目录自动更新，直接改动安装内容会被判为损坏。客制化永远不落在官方原件上，按下面的顺序选路径。

## 1. 先判断要不要动插件

- 只想让模型多一份任务指导 → 写独立 Skill：`~/.agents/skills/<name>/SKILL.md`（个人）或 `<project>/.agents/skills/<name>/SKILL.md`（项目），不需要插件。
- 只想换模型、停用插件、在消息里点名使用 → 用现有设置与输入语法，不需要客制化。

## 2. 三条客制化路径

| 场景 | 路径 | 更新语义 |
| --- | --- | --- |
| 小改自用（改技能文案、删技能、调声明） | 插件详情 →「转为本地副本」 | 转换即停更：内容可编辑、永不自动更新；回官方 = 卸载副本后从目录重装 |
| 要改名、长期自维护、可能回馈官方 | fork：复制源码包目录、改 `plugin.json` 的 `name`、本地导入或登记 Git 市场 | 完全归你，与官方原件互不影响 |
| 内置插件（如 plugin-creator） | 不能转副本，只能 fork | 官方版常在并随目录更新 |

## 3. 转本地副本之后

- 副本内容可编辑：改技能正文、在技能容器根下新增技能子目录都会被重新发现。
- 不改 `plugin.json` 的 `name`：重命名会让清单与安装事实错位。
- 编辑后用 plugin-doctor 排查声明与装载。
- 副本不受检查更新触达，官方发新版也不会提示；想跟进就卸载副本后重装官方版。

## 4. fork 的正确姿势

- 官方源码在开源仓库 `github.com/MalcolmShi/lesschaos-ecosystem` 的 `plugins/` 下，复制整个包目录起步。
- 必改 `name`：与已安装插件同名会被拒绝安装；技能同名会被先装载者遮蔽并记诊断，技能名一并改。
- 改完先经 `builtin.plugin_install` 在对话里试用，稳定后再放固定位置或登记 Git 市场（登记时固定快照，更新靠重新登记）。
- 想回馈官方：向开源仓库提 PR，合并后随官方目录分发。
