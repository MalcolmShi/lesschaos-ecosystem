# 报告整理

1. 从当前要求确定读者、周期与交付格式。优先用已有材料，沿真实来源取得事实；关键数字缺口请数据核验成员或用户补充。完成条件：报告范围明确，事实与待核对事项分开。
2. 按“结论、关键进展或指标、风险、下一步”组织内容；用户当前要求和有效组织规范优先。数字保持来源的单位和口径，推断及建议明确表达。完成条件：每条重要结论可追溯，矛盾和未完成项没有被省略。
3. 在当前任务目录写入文件，重新读取关键数字和来源，交付实际路径及仍需用户决定的事项。同一文件沿协作分工交接。完成条件：文件真实存在，内容可复查；发送或正式提交另按获准意图执行。

## 核验 JSON 转 Markdown

当输入来自数据核验插件的 `checked-data.json`，可用配套 [render_report.py](scripts/render_report.py) 形成基础周报。先核对本机有 Python 3；程序只用标准库、读本机 JSON 并写指定 Markdown，不联网。

```sh
python3 <本Skill目录>/scripts/render_report.py <checked-data.json> <工作目录>/weekly-report.md
```

生成器保留数据缺口和证据，不判断业务好坏、不编造进展或下一步。生成后按真实工作材料补充定性内容并读回核对；输入是 `partial` 时，报告保持“部分数据待核对”。仅从其它来源复制的 JSON 仍须先核对其证据；结构通过不代表业务事实已证实。
